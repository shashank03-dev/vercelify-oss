## Bugs and observations

1. **Low — malformed app-mode forward silently binds a port. Fixed in `c10aac2`.** Put `127.0.0.1:17420=:7420` in the forwards file alongside a valid line. Before the fix the parser accepted both: it checked only that the suffix after the last colon was a numeric port, and never checked the host was nonempty. The bad entry could bind locally but `resolve_target` could not resolve it. The new regression failed before the fix (two valid entries instead of one) and passes afterwards; valid lines remain usable and the malformed entry is reported separately.
2. **Low — Docker-gated tests report success without executing. Fixed in the second sweep (see `docs/BUG-SWEEP-2026-10-29.md`): the seven tests are `#[ignore]`d by default and run with `--include-ignored`.** Run `cargo test -p vercelify-platform` without `VERCELIFY_DOCKER_TESTS=1`; the four Docker-dependent unit cases and two integration cases return immediately, yet the Rust harness labels them `ok`. This can mislead readers about real Docker coverage. Root cause: early returns in the test bodies. Proposed patch: mark these tests ignored by default and provide a documented explicit command such as `VERCELIFY_DOCKER_TESTS=1 cargo test -p vercelify-platform -- --ignored`; adjust CI so the real Docker suite is an explicit gate. This changes suite selection and needs verification on Linux before adopting.

3. **Low — app-mode forward does not recover from a transient bind failure. Fixed in `9ae0306`.** Hold a local port, add that port to the forwards file, then release it. Before the fix the failed task was retained and the unchanged file was never reconsidered. A new test reproduced the timeout; the watcher now retries failed tasks, and the mesh suite passes. The design document was updated in that commit.
4. **Low — workspace did not compile on macOS. Fixed in `db27e01`.** Apple libc declares mutable `openpty` pointer arguments; the original code used const pointers. The original workspace test failed to compile on macOS, while the portable call and a PTY size regression now pass.
5. **Test harness — agent black-box readiness used Linux-only `/proc`. Fixed in `3eb09a6`.** All eight existing black-box tests timed out on macOS because `listens_on` could not inspect `/proc`. The macOS check uses `lsof` to verify the same process owns the listening socket; all eight passed. No expectations were loosened.
6. **Dependency observation — website `npm audit` reports high-severity advisories. Unfixed.** `vgpu@0.5.0` depends on `@modelcontextprotocol/server@2.0.0`, affected by GHSA-jm63-cq47-j5jp and GHSA-46jr-4wx8-v453. The site imports the browser entry and no MCP server exposure was established; do not infer that the static website is exploitable. Proposed patch: update the upstream dependency when a compatible fixed version is available, then verify the site build and visual behavior.

7. **Medium — unreadable app volume source could be treated as an empty source during a storage move. Fixed in `4d6ae09`.** `Path::is_dir()` reports `false` for both missing and inaccessible paths. On a failed filesystem lookup, the move could create an empty target and change its storage-tier record, risking apparent data loss. The move now calls `std::fs::metadata`: it copies existing directories, initializes only truly absent sources, and rejects non-directory or unreadable sources. On failure it restarts the original container without updating the storage tier. The `non_directory_volume_source_must_not_be_treated_as_empty` regression failed before the fix and passed afterward. The system design was updated with the behavior. A separate permission-denied regression remains useful.

8. **Test fixture — registry Docker test assumed `alpine:3.20` was locally cached. Fixed in `f96197a`.** The isolated VM had a working Docker daemon but lacked that image, causing one opt-in platform test to fail. Explicit image preparation made the test pass. The test now pulls its own Alpine fixture before tagging, ensuring independence from prior Docker state.

9. **Medium — push-to-deploy rebuilt migrated apps during the Coolify migration window. Fixed in `25621ee`.** Run `host/tests/contract/migrate.sh` (real Coolify 4.4.6) with the default auto-deploy interval. A git app is migrated with Coolify's recorded commit as its first deployment. Within about a minute of the switch, the agent logged `auto-deploy: site master → 1ce75d0 (#2)` and built the branch head. The contract then failed with "site was built". The migration design promises that the switch builds nothing and that rollback finds Coolify's apps as they were (design §18). A build during that window costs a full build on low-end hardware, and rollback throws its result away. Root cause: `PlatformGit::check` treated the imported deployment's commit as the last-deployed base and found the branch had moved. Fix: while the migration phase is `importing`, `imported` or `switched`, the poller skips previews. It also records "new commit waiting: the move from Coolify isn't finished" without advancing `last_head`, so the pushed commit deploys after `migrate finish`. Regression: `migrate::tests::push_to_deploy_waits_until_the_move_is_finished` (phase table) and the end-to-end contract, which failed before the fix and passes 14/14 after. The contract test was not changed. Not exercised end to end: whether that held commit actually deploys after `finish`. The contract tears down at that point.
10. **Test fixture — Coolify rejected the contract's root email. Fixed in `c4dd177`.** Coolify 4.4.6 validates `ROOT_USER_EMAIL` with `email:rfc,dns`, and `example.com` publishes a null MX record. Coolify stopped with "Invalid Root User Environment Variables". The fixture now uses an address on a domain with mail exchangers. Note: this validation does a DNS lookup, so the contract needs working DNS.

11. **Low — unreadable data directories were reported as missing. Fixed in `858f19f` and `b12b3fb`.** Run `VERCELIFY_DOCKER_TESTS=1 cargo test -p vercelify-platform --test databases_docker` as a non-root Docker user. `move_database` failed with a 404 `NotFound("/var/lib/docker/volumes/vfy-db-pgtest-data/_data doesn't exist")`, though the directory exists and is only unreadable. Nothing was lost: the move stopped and restarted the database. But the error points an operator at missing data rather than the agent's privileges. Root cause: `copy_tree` used the same `Path::is_dir` check as bug 7. Missing, not-a-directory and unreadable sources now return distinct errors. App volume moves now reuse those checks, so they name the path instead of a bare "Permission denied (os error 13)". Regression: `dbengine::tests::copy_tree_says_why_a_source_is_unreadable`, red before and green after.

12. **Medium — adding a second main server closed the wizard before its last step. Fixed in `0775589`.** In the demo, pair one server, open "Add a machine", choose "A server", "Already installed", and pair a second main. Adding a main selects it, which changes the `LiveProvider` key; the wizard sat inside that subtree, so it remounted on its first step (or vanished) instead of showing the checks and "Done". The modal now lives outside the per-server key. Regression: demo E2E "add a second main server: the wizard finishes on it", red before, green after.
13. **Low — a refused port gave no reason. Fixed in `445d2ed`.** In "New app", type port 99999: "Create" was disabled with the hint still reading "Leave empty to detect it". The hint now says "From 1 to 65535". The demo new-app test checks it.
14. **Test harness — two contract checks were racy. Fixed in `e19370d`.** In multinode and promote, `curl … | grep -qi caddy` runs under `pipefail`: `grep -q` exits on the first match, `curl` can then die of SIGPIPE, and the pipeline fails though the page was right. Over 20 runs of the same check, 13 failed. Multi-node's crash check stopped the replica with `docker stop`, which races the reconciler: it starts exited containers every 30 s, so the restart count could stay below the auto-rollback threshold. The check now kills the container's process (a real crash; `--restart unless-stopped` restarts it), as a crash loop does. Done by hand first: the watcher rolled back in 21 s ("deployment #3 restarted 2 times; rolling back"). Expectations unchanged; both pass twice in a row.
15. **Medium — the Apps page told a server whose engine failed to migrate from Coolify. Fixed in `68e2750`.** Start an agent whose platform engine fails (for example a superseded main): `/v1/platform/*` answers 503 "the platform engine failed to start: …", and the Apps page showed the Coolify migration guide. It also counted a worker as a main when the worker role only showed up in health, and listed the current server among "other mains". The page now polls the engine, shows the reason and `sudo vercelify doctor`, and treats a health role of `worker` as a worker. Unit test for `engineDownReason`; checked in the browser against the real agent.
16. **Low — a volume could be mounted inside `/proc` or `/sys`. Fixed in `a5bf6b8`.** `POST /v1/platform/apps/{app}/volumes` with `"mount_path":"/proc/x"` returned 200: only the exact `/proc`, `/sys` and so on were refused. runc refuses a mount inside `/proc` when the container starts, so the next deploy failed far from the cause. Paths under `/proc/` and `/sys/` are now refused when saved; `/etc/nginx/conf.d` stays allowed. Regression: extended `validate::tests`.

17. **Medium — "Create and deploy" didn't deploy. Fixed in `c4a4ba5`.** In the cockpit against a real agent, create a Git or image app: it showed "Not deployed yet" and no deployment existed. The agent only creates the app (services excepted) and the cockpit never asked for a deployment. The demo backend deployed on create and hid it, so the demo tests passed. The cockpit now starts the first deployment, the demo backend behaves like the agent, and the demo test "deploy with a live log" fails without the fix (checked) and passes with it. The live test no longer presses Deploy after creating.
18. **Low — a new domain took up to 30 s to route. Fixed in `23a0e60`.** Adding a domain changed nothing until the next 30-second reconcile (measured 3 to 46 s); a removed one kept answering as long. A reconcile now runs at once, as it already did for stop and start: 0.5 to 2 s for both.
19. **Low — Enter didn't add a domain. Fixed in `62762f0`.** The field wasn't in a form. Checked in the demo E2E.
20. **Medium — a crash-looping app made its deployment wait the full health timeout. Fixed in `61f4b2d`.** A commit with a syntax error failed after 180 s. With a restart policy, Docker reports a crashing container as running between restarts, so the "exited" check never fired. Three restarts now fail the deployment (6 s here); one bad start still gets another chance. Unit test `a_crash_loop_is_given_up_on_without_waiting_for_the_timeout`.
21. **Low — a failed app's log excerpt was out of order. Fixed in `396a8f9`.** stdout came first and stderr after, so the error showed before the lines that led to it. Lines are now merged by their timestamps. Unit test.
22. **Medium — a commit held during a migration showed as an error. Fixed in `2a4d798`.** The hold from bug 9 was written as the watch's last error: the app's card showed a warning and the doctor raised "1 app can't check its branch (a revoked token, a renamed branch)" for the whole move. The power-guard hold did the same. Holds now have their own field (migration 0004, cleared by the next check) and the card says Waiting. The migration contract now checks the hold and, closing the gap noted in bug 9, that the held commit deploys after finish (`1d2e4ed`).
23. **Medium — orphaned containers were never removed on servers outside UTC. Fixed in `82d87ec`.** After the crashes of scenario 3, four containers ran for one app 20 minutes later. `docker ps` prints creation times in the server's zone (`+0530 IST` in this VM, which follows the Mac) and the parser accepted only `UTC`, so an orphan's age was unknown and it was never collected. Unit test `orphans_are_found_on_a_server_outside_utc`, red before and green after; live, the strays went at the first reconcile after the fix.
24. **Low — a first deployment was called live before the proxy routed it. Fixed in `2d41a14`.** Right after "healthy", the first request to a new app's URL got the proxy's 404 two times out of three: Traefik loads a route file about 1.7 s after it is written. 25. **Low — browser mode showed "Bad Gateway" and "signal is aborted without reason". ## Untested scope

The requested broad exploratory matrix is incomplete. Real deployment, redeployment, rollback, real database backups and storage moves, and multi-node mesh behavior have now been exercised in the isolated VM. The scenario tests then covered agent crashes during a build, a health wait and a drain; deploying from the cockpit; a commit held during a migration; update, uninstall and reinstall; a short load, out-of-memory and slow-disk run; and the cockpit with the agent down or frozen. Remaining gaps include interruption during a migration step, preview cap, end-to-end secret exposure, full API authorization matrix, comprehensive path traversal and all oversized-body cases, long-running (hours) load and slow-disk endurance, and comprehensive Bash 3.2 behavior. Existing unit and demo tests cover portions of these but are not substitutes for the requested scenarios.

Real macOS utun/mDNS and DMG installation, physical Raspberry Pi hardware, real CGNAT/Cloudflare Tunnel, and actual laptop battery/lid behavior were not tested. Demo runs do not establish hardware or network behavior.

## Environment and workarounds

A separate 8 GiB Colima VM was started without activating the user’s existing Docker context. Its image download failed with unexpected EOF once, then resumed successfully; Rust debug artifacts were moved to the VM’s 60 GiB data disk when the system disk filled. The requested repository was cloned separately because `/Users/shashank/vercelify` is a different repository with uncommitted changes. Docker is active **only inside the isolated VM**. For real storage-move integration, tests were executed as root inside the VM to access Docker's root-owned volume paths. The live E2E runner used a VM-local test copy with its build step replaced by an assertion that the already-built debug agent exists; the source branch's runner is unchanged. The E2E HDD path `/mnt/vfy-e2e-hdd` is backed by the VM's separate data disk. No host Docker context or firewall was modified. System Chromium/Playwright setup supported both demo and live suites. macOS has BSD rather than GNU userland; Linux Bats and privileged contract tests were run inside the isolated VM.

The migration contract, desktop E2E and installer integration ran in the same VM. The migration contract ran from the shared checkout with an agent built into a VM-local `CARGO_TARGET_DIR`, because the shared `target/debug` holds macOS builds. The desktop and installer suites ran from `/mnt/lima-colima-vercelify-testing/e2e-project`, an rsync of the branch (without `.git`, `target`, `node_modules` or `dist`), with its own Linux `node_modules` and build outputs. The installer binaries were built as arm64 musl release builds in `rust:1-alpine`, the same path `host/lib/agent.sh` uses when no release binary is available. The Coolify contract needs DNS: Coolify validates the root email's domain.
