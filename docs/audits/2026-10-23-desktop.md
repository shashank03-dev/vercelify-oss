# Desktop P1/P2 bug audit — 23 October 2026

Scope: the Tauri cockpit, its React request lifecycle, storage migration, local AI streaming, and credential persistence. Findings below were reproduced by failing regression tests before their fixes. This is a targeted audit, not a guarantee that the app has no remaining bugs.

## Confirmed findings and fixes

| Priority | Bug and user impact | Fix | Regression coverage |
| --- | --- | --- | --- |
| P1 | Switching servers during a volume move changes the destination of subsequent requests. Server A is stopped, but the stop checks, move request, job polling and restart resolve against newly selected server B. Numeric volume IDs can overlap between servers, allowing an unrelated volume to be moved and leaving A offline. | Bind the entire operation to A using `agentOn` and `coolifyOn`; pass A explicitly through job polling. Continue safely on A after the old page unmounts. | `cockpit/src/views/storage.test.tsx`: pause the stop response, unmount the page, select B, then resume; assert all migration requests remain on A, for both legacy and background moves. |
| P2 | New-app creation and auto-deploy setup can change servers between project discovery, app creation and branch-watch registration. This produces cross-server requests, failed creates or incomplete auto-deploy setup. | Bind the modal and auto-deploy panel to the original agent/Coolify clients, including `defaultTarget`. | `cockpit/src/components/server-scoping.test.tsx`: switch away during project discovery and assert creation plus auto-deploy setup stays on A. |
| P2 | Database creation can send a create request to server B with project and server IDs obtained from A after switching during discovery. Creation fails or targets the wrong installation. | Keep all project discovery and database creation requests on the original Coolify installation. | `cockpit/src/components/server-scoping.test.tsx`: pause project discovery, switch to B and assert database creation still targets A. |
| P2 | Display startup failure cleanup, and display stop after a pending local sender stop, resolve the receiver endpoint against the newly selected server. A receiver on A can be left running while B's receiver is stopped. | Bind display requests and cleanup to the server owning the display operation. | `cockpit/src/components/server-scoping.test.tsx`: fail local screen capture after switching away and verify receiver cleanup targets A. |
| P2 | `usePoll` shares one in-flight/alive flag across dependency generations. Changing the requested resource while a request is pending skips the new fetch, then accepts the obsolete result or error. With interval zero, the correct data may never be fetched. Existing data also remains visible for a different resource. | Give every effect lifetime its own request ownership; fetch immediately for new dependencies, discard obsolete responses, clear previous resource data/errors, and retain last good data for refresh failures of the same resource. | `cockpit/src/lib/hooks.test.tsx`: dependency changes during pending requests, obsolete rejections, old data clearing, StrictMode, and failed refreshes. |
| P2 | Credential saves use `OpenOptions::mode(0600)`, which only applies when creating a file. An existing 0644 settings file stays publicly readable after saving agent and Coolify tokens. The in-place writer also follows symlinks and truncates the destination before completing the write. | Write a fresh 0600 file beside the destination, sync it and atomically replace the destination. Publish the new in-memory config only after persistence succeeds. | Native settings tests in `cockpit/src-tauri/src/lib.rs`: replace an existing 0644 file with a private file; replace a symlink without modifying its target. |
| P2 | Stop cannot cancel a native stream before HTTP response headers arrive. A stalled server or model cold start can keep the operation running until the request timeout (up to 15 minutes). | Select cancellation while waiting for headers and while reading an error response, as well as while consuming stream chunks. | `cockpit/src-tauri/src/http.rs`: real loopback TCP server accepts a connection but never sends headers; cancellation must complete promptly and successfully. |
| P2 | Navigating away from AI chat or switching servers leaves model generation running after its UI is gone; a build explanation can also start after its dialog closes during model discovery. This wastes CPU and can occupy the server's single generation slot on low-memory hardware. | Cancel the chat stream when the chat component unmounts. Also prevent a build explanation from starting if its dialog closed during asynchronous model discovery, and bind explanation calls to their original host. | `cockpit/src/views/ai.test.tsx`: start generation through the real AI page, unmount it, and verify stream cancellation. `server-scoping.test.tsx`: close a build explanation during model discovery and verify no generation starts afterward. |

## Verification

- Frontend unit tests (80 tests) and TypeScript/production build.
- Full Playwright demo flow suite (11 flows), plus a targeted rerun of the build-explanation flow after its final lifecycle guard: onboarding, server switching and pooling, AI chat, build explanations, deployments, environment import, server care, domains and project configuration.
- Native cockpit tests (9), core unit/fixture tests (105 + 16), agent unit tests (117), native executable build, workspace Clippy with warnings denied, and formatting checks.
- New regression tests were observed failing on the original implementation and passing with the fixes.

## Environment limitations

The baseline `cargo test --workspace --all-features` run passes the 117 agent unit tests but fails all seven agent integration tests at `agent/tests/e2e.rs:104` (agent readiness timeout). Their `listens_on` implementation requires Linux `/proc/<pid>/fd` and `/proc/net/tcp*`, which are absent on this macOS machine. Affected tests: `agent_end_to_end`, `events_jobs_power_guard_and_domain`, `skipped_builds_and_vercel_json_follow_deploys`, `worker_role_and_missing_ollama`, `background_pass_raises_and_sends_alerts`, `pairing_autodeploy_llm_and_pools`, and `previews_feedback_and_rollback`. These tests run in Linux CI; they are not reported as passing locally.

The repository's native desktop WebDriver suite requires Linux WebKitWebDriver and a live Coolify/agent environment. It was not run here. The Docker daemon is unavailable, so container-based host and Coolify contract suites were not run. Native backend behavior is covered by local Rust tests, including the real TCP cancellation reproduction; UI flows use the demo backend.
