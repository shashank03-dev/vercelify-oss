# Repository bug sweep — excluding website

Scope: agent, platform/core/mesh crates, desktop Rust/React, CLI, host installation,
backup and storage scripts. `website/` was excluded. These findings add to the
previous product audit; they do not certify that no undiscovered bugs remain.

## Fixed P1: physical volume names were not unique

`crates/vercelify-platform/src/volumes.rs::docker_name` joins the application and
volume names with an unescaped hyphen. Both combinations below are valid and
produce exactly the same name:

| Application | Volume | Physical name |
| --- | --- | --- |
| `api-cache` | `data` | `vfy-api-cache-data` |
| `api` | `cache-data` | `vfy-api-cache-data` |

The deployer uses this value as the Docker volume name on SSD and the directory
name on HDD. On the same server, separate apps can therefore share data
unintentionally. Cleanup/purge also derives the same name. The collision was
reproduced by linking a standalone program against the actual platform library
and calling `volumes::docker_name` for both valid names.

The fix stores a unique immutable physical identity (`vfyv2-<volume ID>`) for
new app and database volumes. Previews derive separate names from that identity.
Schema migration 5 leaves existing identities unset, preserving the exact SSD,
HDD and preview locations used by earlier releases. No user data is renamed.
Before mounting, moving or purging legacy volumes, the engine checks for aliases
across apps, databases and registered previews. Ambiguous operations return a
conflict with recovery guidance; metadata and data remain available. Removing
an ambiguous mapping keeps its data on disk. New storage requests use a separate
worker runtime route, so older workers refuse them until upgraded rather than
silently using the legacy name.

Regression coverage includes the original ambiguous owner/name pair, production
versus preview/database namespaces, a real version-4 database upgrade, continued
use of old HDD/SSD paths, and refusal of legacy production/preview aliases.

## Other confirmed issues fixed

| Priority | Finding | Reproduction and correction |
| --- | --- | --- |
| P1 | Concurrent device-token writes lose pairings or fail; an unlocked last-use flush can also race with token mutation. | 24 simultaneous creations failed before the fix. File locking now covers read-modify-write in creation, revocation and last-use persistence, including the CLI's separate processes. A 16-process real-CLI test verifies every record survives. |
| P1 | Overlapping volume-copy source/destination deletes source data. | Passing the same directory erased its database marker before copy failed. Canonical path overlap checks now reject identical, ancestor, descendant and symlink-alias paths before deletion. |
| P1 | Simultaneous desktop process starts leave live children outside the tracked slot. | 24 simultaneous starts followed by Stop left 23 processes alive in the reproduction. Stop/spawn/publish is now serialized under one lock. |
| P1 | Forced environment export leaves secrets readable through an existing public file. | `VFY_FORCE=1 vfy env pull` over a 0644 file retained 0644 despite reporting mode 600. Export now writes a private temporary file and atomically replaces the destination; directories/symlinks are refused. |
| P2 | A damaged token registry is silently overwritten during pairing. | Creating a token over malformed registry JSON succeeded and replaced the old bytes. Mutation now reports invalid data and preserves the file. Authentication still fails closed on unreadable/invalid registries. |
| P2 | Browser HTTP deadlines end at response headers instead of the body. | A server returning headers but stalling its body never timed out. The abort deadline now covers body consumption and produces the normal timeout message. |
| P2 | Custom backup passwords are interpreted as shell syntax. | A password with spaces, dollar signs and quotes made backup setup fail or changed the loaded value. Passwords and supplied S3 credentials now use POSIX single-quoted literals, and the agent decodes the same syntax without evaluating it. Cross-reader tests cover quotes, backslashes, dollar signs and multiline values. |

## Additional storage issues found and fixed

| Priority | Finding | Correction and validation |
| --- | --- | --- |
| P1 | A missing file-based database snapshot deletes live data before restore fails. | Restores now stage the complete backup in a private temporary directory, check the producer exit status, and validate file archives before stopping the database or deleting files. A live Redis test reproduced an erased key before the fix and requires the key to survive a failed restore. Staging uses disk space proportional to the backup and is removed after the operation. |
| P1 | App tier moves stop only the routed container while other replicas/sidecars can keep writing. | Stop every production writer, including containers retained during rollout, serialize against reconciliation/restart/deployment of that app, and check actual placement before copying. Linux coverage moves a two-replica app between SSD/HDD, verifies every previous writer stopped and verifies data and ownership survive. |
| P2 | Concurrent database starts race to create the same container. Reconciliation can also restart a database during a move/restore. | Per-database locks cover ensure, move, backup, restore and removal. A real Docker regression reproduced the duplicate-container error before the fix; both simultaneous starts must now succeed. Different databases retain independent locks. |

## Validation and workspace boundary

Regression tests cover the corrected behaviors, including before/after
reproductions for token writes, process starts, export permissions, request
deadlines, volume naming, concurrent database starts and failed restores. Checks include the actual CLI process/token-file boundary,
filesystem data-preservation assertions, live child-process cleanup, browser
request timing, and Debian Bats tests for secret export and backup setup.

Separate screencast changes appeared concurrently in this shared workspace in
`agent/src/display.rs`, `agent/src/routes.rs`, desktop supervision,
`crates/vercelify-core/src/stream.rs`, examples and the
screencast contract. Those were not authored or reset by this sweep. The fixes
above are kept separate from that work. No website files were modified.

Final validation: the isolated staged source passed the Rust workspace tests and
Clippy, 90 cockpit unit tests and 21 demo browser flows. Linux validation passed
176 host Bats tests, both real-Docker storage suites (including two app replicas,
legacy database data, backups, failed restore and purge), 7 live browser flows,
and 6 native Tauri desktop flows. A separate wire-level test covers older workers.
